🛡️ Three Boundaries of Idempotency
Architecture
1. Application-Level Idempotency Gateway

Deduplicates client retries using SHA-256(canonical JSON). Same key + payload returns the cached HTTP response directly from PostgreSQL without re-executing business logic.

▼ Passes derived key: gateway-8f1a2b3c
2. Provider-Level Idempotency Downstream Provider

The external processor receives a deterministic provider-scoped key derived from the client key. Ensures network-level retries do not trigger duplicate credit card charges.

▼ On timeout or crash recovery
3. Reconciliation & Recovery Loop Self-Healing

When gateway state is ambiguous (timeout, stale lock >30s, crash before DB commit), gateway queries provider by provider_idempotency_key before retrying. If already charged, reconciles to COMPLETED.
